# Security Policy

## Supported versions

The latest release receives security fixes. A severe issue may also receive a
patch on the immediately previous minor line when a safe fix can be maintained.
Older versions should be upgraded before reporting a compatibility defect.

## Report privately

Use [GitHub private vulnerability reporting](https://github.com/trugurpala/divan/security/advisories/new).
Do not publish credentials, private project data, exploit details or suspected
prompt-injection payloads in an issue or discussion.

Include the affected version, host, impact, smallest safe reproduction and any
known mitigation. Remove usernames, email addresses, absolute paths, tokens and
customer data.

## Response targets

- Initial acknowledgement target: 72 hours.
- Triage target: seven days.
- Fix and disclosure timing depends on severity, exploitability and downstream
  coordination. These are response targets, not a paid support guarantee.

## Scope

Reports may cover installer or update authority, transaction recovery, secret
leakage, unsafe tool instructions, supply-chain provenance, license boundaries,
local status server exposure and release integrity.
