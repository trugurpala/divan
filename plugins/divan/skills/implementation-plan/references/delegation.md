# Delegate with compact evidence

The coordinator owns the user's outcome, scope, integration, and final verification.
Use the host's available subagent tools. A skill called a worker is reference
material until an actual agent is dispatched; do not invent a runtime or a permanent
background team to complete an ordinary task.

Delegate only independent work with a clear benefit. Give each agent:

- the concrete outcome and minimum relevant context or file pointers;
- exclusive write ownership or an explicit read-only boundary;
- dependencies, constraints, and the user's authorization;
- the acceptance check and expected evidence;
- a stopping condition and the question to escalate if blocked.

Keep messages compact: **changed state; evidence; blocker or decision needed; next
action**. Send meaningful changes, not repeated unchanged status or complete chat
transcripts. Load only the skill/reference for the assigned task. Preserve actual
technical detail needed for correctness; never trade it away just to claim fewer tokens.

Serialize changes to shared files. If findings invalidate the plan, communicate the
specific conflict before dependent work continues. The coordinator reads returned
diffs, resolves conflicts, and runs current integration checks; a worker's success
statement alone is not proof.

For a substantial product choice or change, an independent reviewer can check the
result against the original user workflow and repository contract. Give the reviewer
raw requirements, diff, and check outputs without prescribing the verdict. Prioritize
material gaps and testable corrections, then close them with fresh evidence.

End with a verified result and a concise continuation note in the existing project
document. Ongoing monitoring or work after the conversation requires a separately
requested scheduler/service; an active subagent does not imply a persistent process.
