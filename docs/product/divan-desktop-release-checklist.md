# Divan Desktop Windows Release Checklist

This file is the canonical remaining-work checklist for the first stable Divan Desktop Windows release.

The gate IDs are intentionally stable. Do not renumber or silently remove a gate. A gate becomes `DONE` only when its evidence exists; partial implementation remains `OPEN` or `IN PROGRESS`.

Divan Core remains authoritative for task state, mandate, evidence, review, approval, merge and release. Orca remains a replaceable execution engine behind the Divan execution contract.

## Already established

- Persistent task lifecycle from draft through release.
- Mandate-gated mutation and no synthetic PASS path.
- Native Git-worktree execution for supported local coding agents.
- Orca adapter behind the replaceable `ExecutionEngine` / `ExecutionRouter` boundary.
- Independent Codex/Claude reviewer selection and review-to-diff binding.
- Approval rejects dirty/stale/tampered review state and merges with `git merge --ff-only`.
- SHA-256 execution/review/approval evidence.
- Project registration, bounded Windows tool discovery, settings, evidence and diff UI.
- Operator-selectable worker and execution engine without changing Core authority.
- Self-contained PyInstaller Core sidecar and NSIS current-user installer.
- Installed-app Windows smoke test with exact source commit/tree provenance.
- Optional signed-updater feature; unsigned beta builds cannot claim stable updater capability.
- Explicit update check and separate user-confirmed install flow.
- Interrupted execution is persisted before engine invocation and recovered fail-closed to explicit RETRY; restart never silently resumes mutation.
- Manual, main-only real-user acceptance and signed-candidate workflows.
- Dedicated `divan-desktop-acceptance` runner label and attested acceptance evidence contract.
- Authenticode/updater/signature/source-provenance stable-release gates are fail-closed.
