# v0.17.1 target — Vibe-friendly progress

## Mandate

Keep Divan technically powerful in the background while making substantial
work understandable in the conversation to a vibe coder. Preserve one Divan,
the existing modular engine, the Hükümdar authority boundary, and all current
runtime and compatibility contracts.

## User outcome

During a long task, the user receives short, truthful updates that answer:

1. What is Divan doing now?
2. Why does it matter?
3. What meaningful outcome comes next?

The user does not need to interpret commands, paths, hashes, raw logs, or the
activity of individual subagents.

## In scope

- One canonical progress-language reference under the Sadrazam skill.
- Shared links from all seven public chat entry commands.
- Stable phase language, cadence, blocker, accessibility, and evidence rules.
- Turkish vibe-coder guidance and synchronized English/Turkish public surfaces.
- Release-manifest coverage for previously untracked public commands and the
  new contract.
- Focused regression tests, full canonical verification, independent review,
  PR/CI, merge, patch release, Pages, and Wiki readback.

## Explicitly out of scope

- Modifying the native Codex or Claude Code user interface.
- Adding a new engine module, daemon, hosted service, MCP server, external
  repository, or third-party runtime dependency.
- Exposing hidden chain-of-thought, secrets, private scratch work, or raw logs.
- Claiming independent adoption or changing v1 readiness beyond 7/8.

## Acceptance criteria

1. Sadrazam and `/divan`, `/ferman`, `/sefer`, `/teftis`, `/yayin`, `/defter`,
   and `/vezir` use one canonical progress contract without duplicated protocol
   text and resolve it only from the loaded-plugin root.
2. The contract separates planning, coding, testing, GitHub delivery, merge,
   publication, and live verification claims.
3. Updates are short, phase-based, user-centered, translated to the user's
   English or Turkish language, and do not rely on invented percentages,
   color, emoji, or Ottoman metaphor as the only status carrier.
4. Existing runtime behavior, module count, authority order, package inventory,
   and compatibility surfaces do not change.
5. README, Wiki, Pages source, value guide, package metadata, changelog,
   blueprint, progress record, and release manifest agree on v0.17.1.
6. Focused tests, impact-required checks, the full canonical verifier,
   `git diff --check`, and an independent review report no open blocker.
7. PR checks pass without bypass, the immutable v0.17.1 release is published,
   and assets, Pages, and Wiki are read back before completion is claimed.
8. Repository checks prove the communication contract and its public surfaces;
   they do not claim a new real-agent A/B result without a redacted host eval.


## Rollback

Before merge, drop the focused branch. After merge but before publication,
revert the patch. After publication, never move the tag; publish a corrective
patch. The v0.17.0 runtime and compatibility contracts remain unchanged.
